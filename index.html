How it works

Two API calls. Absolute trust.

01 — Certify

Issuer API

The university sends document metadata and the SHA-256 hash of the PDF. MOTSA returns a certificate ID, a QR code, and a permanent verification URL.

02 — Verify

Verification API

The HR team uploads the received PDF or scans the QR code. MOTSA recomputes the hash locally and compares it to the certified version — nothing is sent to our servers.

03 — Result

Clear outcome

No vague scores. The result is Verified, Modified, or Unknown — with full issuer and holder details attached.

API reference

Clean, predictable endpoints

RESTful JSON API. Authenticate with a bearer token. Two endpoints cover the full certification lifecycle.
